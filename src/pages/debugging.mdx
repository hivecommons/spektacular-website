## Enabling debug logging

Debug logging is off by default. Every project scaffolded by `spektacular
init` already has the key in `.spektacular/config.yaml`, just set to
`false`. Turn it on by editing that file:

```yaml
debug:
  enabled: true
```

To record a session without editing the config, set
`SPEKTACULAR_SESSION_LOG=on` in the environment your agent runs in. Every
`spektacular` command it runs is recorded, whatever `debug.enabled` says.
Setting it to `off` does the opposite: a command run with it is left out
of the log even when debug logging is on, which suits a tool that polls
`status` every few seconds.

## What gets logged

Once enabled, every `spektacular` command appends one line to a session
log file under `.spektacular/debug/`. Each spec, plan or implement
workflow gets its own file, named for when it started, the agent the
project is set up for, and the workflow, for example
`20261001T090334.911373161Z_claude_plan_000008_debugging-docs.jsonl`.
Commands run with no workflow in progress share a `no-active-workflow`
file. When an epic is planned or implemented, each spec's workflow runs
in its own lane and writes its own file, so specs worked on side by side
never share one. Starting a workflow again, for example with `--force`,
begins a new file. Files are never truncated or rotated: each command
adds one more line.

Here's a real sample line:

```json
{
  "seq": 0,
  "timestamp": "2026-07-03T11:31:53.075772108+01:00",
  "session_id": "no-active-workflow",
  "command": ["knowledge", "sources"],
  "duration_ms": 0,
  "exit_code": 0,
  "response": "{...full JSON stdout response as a string...}",
  "state_before": null,
  "state_after": null,
  "advanced": false
}
```

- `seq`: this line's position in the file, starting at 0.
- `timestamp`: when the command ran.
- `session_id`: `"no-active-workflow"` when no spec, plan, or implement
  workflow is in progress, or `"<kind>:<name>"` (for example
  `"plan:000008_debugging-docs"`) when one is active.
- `command`: the CLI arguments the command was invoked with.
- `duration_ms`: how long the command took to run.
- `exit_code`: the command's exit code.
- `response`: the command's full JSON output, as a string.
- `state_before` / `state_after`: the workflow's state before and after
  this command, or `null` when no workflow is active.
- `advanced`: whether this command moved the workflow state machine
  forward.

## Before you enable it

The default `.spektacular/.gitignore` ignores `*.log`, but session log
files end in `.jsonl`, so that pattern doesn't match them. If you enable
debug logging, consider adding `.spektacular/debug/` to your own
project's `.gitignore` so the growing log files don't end up committed.
